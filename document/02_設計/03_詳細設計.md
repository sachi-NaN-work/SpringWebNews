## 2. アプリケーション構成

### 2.1 採用方式

| 項目                                        | 仕様                               |
|-------------------------------------------|----------------------------------|
| Java                                      | Java 21                          |
| Web フレームワーク                               | Spring Boot 3.5 系、Spring WebFlux |
| テンプレート                                    | Thymeleaf                        |
| 認証・認可                                     | Spring Security（WebFlux）         |
| DB アクセス                                   | Spring Data R2DBC                |
| RDBMS                                     | PostgreSQL                       |
| キャッシュ・一時データ                               | Redis                            |
| イベント配信                                    | Kafka                            |
| 推薦モデル実行                                   | ONNX Runtime                     |
| API 仕様の生成（API の URL、入力値、返却値などの情報を自動でまとめる） | springdoc-openapi                |
| API 仕様の表示（API の仕様をブラウザで確認・実行する）           | Swagger UI                       |
| 監視・状態確認（アプリが正常に動いているか、現在の状態を確認）           | Spring Boot Actuator             |
| 監視情報の収集（推薦処理時間などの数値を集める）                  | Micrometer                       |
| 監視情報の保存・確認（集めた数値を保存し、あとから確認する）            | Prometheus                       |
| 非同期戻り値                                    | 単一結果は `Mono<T>`、複数結果は `Flux<T>`  |


<br>

### 2.2 実装フォルダ構成

```text
src/main
│
├── java/com/news/recapp
│   │
│   ├── NewsApplication.java                  # アプリケーション起動入口
│   │
│   ├── application                           # アプリケーション層
│   │   ├── dto/ApiDtos.java                  # API・推薦用 DTO
│   │   ├── exception                         # 業務例外
│   │   ├── metrics                           # 推薦メトリクス
│   │   ├── port/out                          # 外部データ・機能の出力ポート
│   │   └── service                           # 業務サービス
│   │
│   ├── config                                # 設定層
│   │
│   ├── data                                  # データ層
│   │   ├── kafka/adapter                     # Kafka アダプタ
│   │   ├── onnx/service                      # ONNX モデル実行
│   │   ├── r2dbc/adapter                     # PostgreSQL アダプタ
│   │   └── redis/adapter                     # Redis アダプタ
│   │
│   ├── persistence                           # DB アクセス層
│   │   ├── entity                            # R2DBC エンティティ
│   │   └── repo                              # R2DBC リポジトリ
│   │
│   ├── presentation                          # プレゼンテーション層
│   │   ├── advice                            # 共通例外・共通画面属性
│   │   ├── openapi                           # API 説明
│   │   ├── security                          # 認証ユーザー、ロックアウト
│   │   └── web                               # 画面・API コントローラ
│   │
│   └── util                                  # メッセージ取得
│
└── resources
    ├── messages*.properties                  # 表示メッセージ
    ├── static                                # CSS、JavaScript、画像
    └── templates                             # Thymeleaf テンプレート
```

<br>


### 2.3 レイヤ責務

| レイヤ                      | 主な責務                                                     |
|--------------------------|----------------------------------------------------------|
| プレゼンテーション層（presentation） | ユーザーからの入力を受け取り、入力内容を確認して、画面や API の処理結果を返却する              |
| アプリケーション層（application）   | ニュース表示、推薦、登録、管理などの業務処理を実行し、DB や外部サービスを利用するための呼び出し方法を定義する |
| データ層（data）               | PostgreSQL、Redis、Kafka、ONNX 等との接続処理を実装する                 |
| DB アクセス層（persistence）    | PostgreSQL に保存するデータの構造と、データを検索・保存する仕組みを定義する              |
| 設定層（config）              | システムの動作条件、接続先、認証・認可、利用する機能などの設定を定義する                     |

## 4. 画面・HTTP エンドポイント設計

### 4.1 一般画面

| 機能          | パス                 | HTTP | 内容                                                                                         |
|-------------|--------------------|------|--------------------------------------------------------------------------------------------|
| ログイン画面表示    | `/login`           | GET  | ログイン画面を表示する                                                                                |
| ログイン        | `/login`           | POST | Spring Security によりユーザー認証を行い、成功時は `/`、認証失敗時は `/login?error`、ロックアウト時は `/login?locked` へ遷移する |
| ログアウト       | `/logout`          | POST | Spring Security によりログアウト処理を行い、`/login?logout` へ遷移する                                        |
| トップ         | `/`                | GET  | `category`、`hashtag`、`ab` を受け取り、カテゴリ一覧、最新・全件・カテゴリ別・ハッシュタグ別ニュース、推薦記事、お気に入り一覧を取得してトップ画面を表示する |
| ニュース詳細      | `/news/{id}`       | GET  | 指定したニュースの詳細、カテゴリ一覧、推薦記事、お気に入り状態・一覧、ログインユーザーのリアクション状態を取得してニュース詳細画面を表示する                     |
| マイページ       | `/mypage`          | GET  | ログインユーザー情報と各管理機能の権限有無を取得し、利用可能なメニューを表示する                                                   |
| パスワード変更画面表示 | `/mypage/password` | GET  | ログインユーザー情報を取得してパスワード変更画面を表示する                                                              |
| パスワード変更     | `/mypage/password` | POST | 現在のパスワード、新しいパスワード、確認用パスワードを検証してパスワードを変更し、結果メッセージ付きで同画面へ遷移する                                |
| 無操作タイムアウト   | `/timeout`         | GET  | セッションを破棄し、タイムアウトメッセージを付与して `/error` へリダイレクトする                                              |
| エラー         | `/error`           | GET  | `msg` パラメータのエラーメッセージを共通エラー画面に表示する                                                          |


<br>


### 4.2 ニュース参照 API

| 機能         | パス                 | HTTP | 内容                                                                                         |
|------------|--------------------|------|--------------------------------------------------------------------------------------------|
| カテゴリ一覧取得   | `/api/categories`  | GET  | 有効なカテゴリを名称順で取得し、`id`、`slug`、`name` を返却する                                                   |
| 最新ニュース一覧取得 | `/api/news/latest` | GET  | 公開対象の最新ニュースを設定件数まで取得し、`id`、`categoryId`、`title`、`publishedAt` を返却する                        |
| ニュース詳細取得   | `/api/news/{id}`   | GET  | `id`（UUID）で指定した有効なニュースを取得し、`id`、`categoryId`、`title`、`body`、`publishedAt`、有効なハッシュタグ一覧を返却する |


<br>


### 4.3 推薦・ユーザー操作 API

| 機能        | パス                                  | HTTP | 内容                                                                                                                                           |
|-----------|-------------------------------------|------|----------------------------------------------------------------------------------------------------------------------------------------------|
| 推薦記事取得    | `/rec`                              | GET  | `k`（取得件数）と `ab`（A / B 区分）を受け取り、ログインユーザーの推薦記事を算出する。`userId`、`ab`、`topK`、`tookMs`、推薦記事一覧 `items` を返却する                                         |
| フィードバック登録 | `/feedback`                         | POST | JSON の `newsId`、`feedbackType`、`source`、`eventId`、`requestId` を受け取り、閲覧・Good・Bad・お気に入り等のフィードバックを記録する。正常時は `status=ok`、重複時は `status=dup` を返却する |
| お気に入り切替   | `/api/favorites/{newsId}/favToggle` | POST | `newsId`（UUID）と任意の `source`、`eventId` を受け取り、お気に入り状態を切り替える。`newsId`、切替後の `favorite`、登録件数 `count`、`message` を返却する。上限超過時は HTTP 409 を返却する        |


<br>


### 4.4 管理画面

| 機能                | パス                                         | HTTP | 内容                                                                                    |
|-------------------|--------------------------------------------|------|---------------------------------------------------------------------------------------|
| ユーザー作成画面表示        | `/mypage/admin/user/create`                | GET  | ログインユーザー情報と選択可能なロール一覧を取得してユーザー作成画面を表示する                                               |
| ユーザー作成            | `/mypage/admin/user/create`                | POST | ユーザー名、パスワード、確認用パスワード、ロール、有効状態を検証してユーザーを作成し、結果メッセージ付きで同画面へ遷移する                         |
| ユーザー有効化・無効化画面表示   | `/mypage/admin/user/enabled`               | GET  | ユーザー一覧と現在の有効状態を取得して管理画面を表示する                                                          |
| ユーザー有効化・無効化       | `/mypage/admin/user/enabled`               | POST | 指定ユーザーの有効状態を更新する。ログイン中の自分自身を無効化する操作は禁止する                                              |
| ユーザー権限変更画面表示      | `/mypage/admin/user/role`                  | GET  | ユーザー一覧と選択可能なロール一覧を取得して権限変更画面を表示する                                                     |
| ユーザー権限変更          | `/mypage/admin/user/role`                  | POST | 指定ユーザーのロールを変更する。ログイン中の自分自身を一般ユーザーロールへ降格する操作は禁止する                                      |
| カテゴリ作成画面表示        | `/mypage/admin/news/category/create`       | GET  | カテゴリ作成画面を表示する                                                                         |
| カテゴリ作成            | `/mypage/admin/news/category/create`       | POST | `slug` と `name` を受け取り、入力内容を検証してカテゴリを作成し、結果メッセージ付きで同画面へ遷移する                            |
| カテゴリ有効化・無効化画面表示   | `/mypage/admin/news/category/disable`      | GET  | 全カテゴリと現在の有効状態を取得してカテゴリ管理画面を表示する                                                       |
| カテゴリ有効化・無効化       | `/mypage/admin/news/category/disable/{id}` | POST | 指定したカテゴリの現在の有効状態を取得し、有効・無効を反転して更新した後、カテゴリ管理画面へ遷移する                                    |
| ニュース作成画面表示        | `/mypage/admin/news/article/create`        | GET  | 有効なカテゴリ一覧と有効なハッシュタグ一覧を取得してニュース作成画面を表示する                                               |
| ニュース作成            | `/mypage/admin/news/article/create`        | POST | カテゴリ、タイトル、本文、ハッシュタグを検証してニュースを作成する。ハッシュタグは有効なものを1～5件指定し、ニュースとハッシュタグの関連を同一トランザクションで登録する |
| ニュース有効化・無効化画面表示   | `/mypage/admin/news/article/disable`       | GET  | カテゴリ一覧とニュース一覧を取得し、ニュースの公開日時、カテゴリ、タイトル、有効状態を管理画面に表示する                                  |
| ニュース有効化・無効化       | `/mypage/admin/news/article/disable/{id}`  | POST | 指定したニュースの現在の有効状態を取得し、有効・無効を反転して更新した後、ニュース管理画面へ遷移する                                    |
| ハッシュタグ管理画面表示      | `/mypage/admin/hashtag/master`             | GET  | 全ハッシュタグと現在の有効状態を取得してハッシュタグ管理画面を表示する                                                   |

## 6. 認証・認可設計

### 6.1 認証

| 項目     | 内容                         |
|--------|----------------------------|

| ログイン画面 | ユーザー ID とパスワードを入力して認証する    |
| 認証成功時  | トップ画面へ遷移する                 |
| 認証失敗時  | エラーメッセージを表示し、ログイン画面を再表示する  |
| ログアウト  | セッションを終了し、ログイン画面へ遷移する      |


<br>


### 6.2 認可

| 項目     | 内容                                      |
|--------|-----------------------------------------|
| 認証不要画面 | ログイン画面、エラー画面、認証不要とした API・静的ファイルを利用可能とする |
| 一般ユーザー | 一般画面、ニュース参照、お気に入り、推薦機能を利用できる            |
| 管理者    | 一般ユーザー機能に加え、管理機能を利用できる                  |
| 権限管理   | ユーザーに設定された権限により利用可能な機能を判定する             |


<br>


### 6.3 ログインロックアウト

| 項目    | 内容                         |
|-------|----------------------------|
| 判定単位  | ユーザー ID 単位で管理する            |
| 判定条件  | ログイン失敗回数が上限に達した場合          |
| ロック中  | ログインを受け付けない                |
| ロック解除 | 一定時間経過後、または認証成功時に失敗状態を解除する |


<br>


### 6.4 無操作タイムアウト

| 項目        | 内容                                                       |
|-----------|----------------------------------------------------------|
| 判定条件      | 一定時間操作が行われなかった場合                                         |
| 最終操作時刻    | 同一ブラウザ内の複数タブで最終操作時刻を共有する                                 |
| タイムアウト時   | セッションを終了し、タイムアウト画面を表示する                                  |
| 保存領域利用不可時 | 複数タブ間で最終操作時刻を共有できない場合は、<br/>タブ内の保存領域へ切り替えて無操作タイムアウトを継続する |
| 設定        | タイムアウト時間は設定ファイルで変更できるものとする                               |

| 302   | 画面遷移     |
| 400   | 入力エラー    |
| 401   | 認証エラー    |
| 403   | 権限エラー    |
| 404   | データ不存在   |
| 409   | 重複・競合エラー |
| 500   | システムエラー  |


<br>


### 12.3 エラー画面

| 項目     | 内容                        |
|--------|---------------------------|
| 画面表示   | エラー内容に応じた画面を表示する          |
| メッセージ  | ユーザーに分かりやすいエラーメッセージを表示する  |
| API 応答 | エラー内容に応じた HTTP ステータスを返却する |


<br>


### 12.4 処理継続方針

| 処理                     | 区分     | 失敗時の動作                       |
|------------------------|--------|------------------------------|
| お気に入り登録・解除             | 主処理    | エラーとして扱う                     |
| お気に入り操作後のフィードバック記録     | 補助処理   | 警告ログを出力してお気に入り結果を維持する        |
| PostgreSQL へのフィードバック保存 | 主処理    | エラーとして扱い、成功応答しない             |
| Redis の推薦シグナル更新        | 補助処理   | 警告ログを出力して後続処理を継続する           |
| Redis のユーザープロファイル更新    | 補助処理   | 警告ログを出力して後続処理を継続する           |
| Kafka へのイベント送信         | 補助処理   | 警告ログを出力して後続処理を継続する           |
| 学習済みモデルによる評価           | 代替可能処理 | 固定係数、基本評価の順でフォールバックする        |
| 複数タブ間の最終操作時刻共有         | 代替可能処理 | タブ内の保存領域へ切り替えて無操作タイムアウトを継続する |


 > 補助処理の失敗は、主処理または独立した後続処理を停止させる理由としない。
